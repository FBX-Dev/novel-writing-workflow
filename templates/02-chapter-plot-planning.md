# 子技能2：单章剧情推演

## 技能概述
基于大纲推演本章核心冲突与转折

## 适用场景
资料整理完成后，正文生成前调用

## 输入格式
- 本章章节号
- 前文状态报告（来自子技能1）
- 用户提供的方向或要求（可选）
- 大纲和细纲文档

## 输出格式
本章剧情推演报告，包含：
- 本章核心冲突
- 3-5个关键事件
- 人物互动设计
- 伏笔埋设/回收计划
- 章末钩子设计

## 执行步骤

### 1. 分析本章定位
- 读取`大纲细纲/全书大纲.md`确定本章在整体剧情中的位置
- 读取`大纲细纲/章节细纲.md`获取本章预设方向
- 判断本章类型：
  - 开端章（引入新线索）
  - 发展章（推进冲突）
  - 高潮章（冲突爆发）
  - 过渡章（缓和节奏）
  - 结尾章（阶段性收束）

### 2. 设计核心冲突
- 基于前文状态和用户要求
- 设计本章的核心冲突：
  - 人物之间的冲突
  - 人物与环境的冲突
  - 人物内心的冲突
- 确保冲突有必要性和合理性

### 3. 规划关键事件（3-5个）
- 事件1：开篇事件（吸引读者）
- 事件2：发展事件（推进冲突）
- 事件3：转折事件（意外发生）
- 事件4（可选）：高潮事件（冲突升级）
- 事件5（可选）：收尾事件（章末悬念）

每个事件包含：
- 事件描述
- 参与人物
- 预期效果
- 字数分配建议

### 4. 设计人物互动
- 基于人物性格和当前状态
- 设计符合人设的对话和反应
- 确保人物关系有推进
- 标记重要对话要点

### 5. 规划伏笔
- 检查有哪些伏笔需要回收
- 设计新伏笔的埋设（如有必要）
- 填写伏笔信息：
  - 伏笔编号（自动生成，格式：F-XXX）
  - 埋设章节
  - 伏笔内容
  - 预计回收章节

### 6. 设计章末钩子
- 设计让读者想看下一章的悬念
- 钩子类型：
  - 疑问型（留下未解之谜）
  - 危机型（主角陷入困境）
  - 转折型（意外事件发生）
  - 情感型（情感冲突达到高点）

### 7. 生成剧情推演报告
整合以上设计，生成详细报告

## 输出示例

```
【第5章剧情推演报告】

== 本章定位 ==
发展章 - 推进"项链能力"主线，回收伏笔F-002

== 核心冲突 ==
张三想测试项链能力 vs. 李明警告可能有危险

== 关键事件 ==
事件1：张三在教室偷偷测试项链，发现能看见"光影"
事件2：李明注意到张三的异常，私下警告他
事件3：放学后张三追着光影到旧校舍，发现秘密房间
事件4：在秘密房间找到半本日记，记载着"光影"的真相
章末钩子：日记最后一页画着一个张三熟悉的符号

== 人物互动 ==
• 张三 & 李明：从试探到半信任，李明透露部分信息
• 张三独白：对能力的恐惧和好奇

== 伏笔处理 ==
• 回收：F-002（项链的真正能力）
• 埋设：F-004（半本日记的来源）
• 埋设：F-005（熟悉的符号与主角的关系）

== 章末钩子 ==
日记最后一页的符号，正是张三小时候在梦中见过的！
```

## 注意事项
- 推演时考虑节奏，避免一章信息量过大
- 确保事件之间有因果关系
- 伏笔埋设要自然，不能太明显也不能太隐蔽
- 章末钩子要与下章有连接性

## 调用示例

**输入**：
```
推演第5章剧情
要求：回收"项链能力"伏笔，埋下新线索
```

**输出**：
```
已完成第5章剧情推演。
核心设计：通过测试项链能力引向秘密房间的发现。
建议在章末揭示日记符号与主角童年记忆的关联，形成强悬念。
是否按此推演生成正文？
```
